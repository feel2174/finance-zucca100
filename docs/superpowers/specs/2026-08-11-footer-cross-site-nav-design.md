# 하단 내비게이션(사이트 내 카테고리 + 포트폴리오 사이트 교차 링크) 설계

**Date:** 2026-08-11
**Status:** Approved

## Background

`finance-hub`(금융바로, finance.zucca100.com)는 `zucca100.com` 포트폴리오의 일부이며, 형제
사이트로 `청구친구`(claim.zucca100.com, 생명·손해보험금 청구 바로가기 허브)가 있다. 현재
`SiteFooter.tsx`에는 청구친구로 가는 링크가 브랜드명만 노출하는 한 줄 문구로만 존재하고, 이 사이트
자체의 카테고리(은행/증권사/저축은행) 페이지로의 하단 내비게이션은 없다.

또한 현재 푸터 텍스트는 청구친구의 옛 후보 브랜드명이었던 "청구창구"를 그대로 쓰고 있다.
`claim-hub-prototype.html`(청구친구 실제 배포 소스) 확인 결과 5개 페이지 전부 "청구친구"로
브랜드명이 확정되어 있어, 이 사이트의 표기가 최신 상태와 어긋난 상태다.

## Goal

하단(푸터) 내비게이션을 추가해 (1) 이 사이트 내 카테고리 페이지 탐색을 돕고 (2) 청구친구로의
검색 유입 가능성이 있는 실제 키워드형 앵커 텍스트로 사이트간 교차 유입을 유도한다. 부수적으로
브랜드명 오타를 수정한다.

## Design

### 1. 브랜드명 수정

`SiteFooter.tsx`에서 "청구창구" 문자열을 "청구친구"로 변경. `href`는 이미
`https://claim.zucca100.com/`로 올바르므로 변경 없음.

### 2. 하단 내비게이션 2단 그리드

`SiteFooter.tsx` 상단(현재 안내 문구 자리)에 2개 컬럼으로 구성된 nav 섹션을 추가한다.

**컬럼 1 — "이 사이트" (내부 카테고리 페이지)**

| 앵커 텍스트 | 링크 |
|---|---|
| 은행 홈페이지·앱 바로가기 | `/?type=bank#explorer` |
| 증권사 MTS 다운로드 | `/?type=securities#explorer` |
| 저축은행 고객센터·앱 바로가기 | `/?type=savings#explorer` |

**컬럼 2 — "청구친구 · 보험금청구 허브" (포트폴리오 사이트 교차 링크)**

| 앵커 텍스트 | 링크 |
|---|---|
| 생명보험금 청구 바로가기 | `https://claim.zucca100.com/#life` |
| 손해보험금 청구 바로가기 | `https://claim.zucca100.com/#nonlife` |
| 실손24 간편청구 안내 | `https://claim.zucca100.com/silson24.html` |

앵커 텍스트는 `claim-zucca100/data/*.tsv`에서 확인된 실제 검색 유입 타이틀 패턴("OO 고객센터
앱 다운로드 바로가기" 류)에 맞춰 일반 라벨("바로가기") 대신 구체적 키워드형 문구를 사용한다.
청구친구 링크의 실제 대상 페이지(`#life`, `#nonlife`, `silson24.html`)는 청구친구
`claim-hub-prototype.html`의 실제 nav(`site-nav`)에 존재하는 앵커를 그대로 재사용한 것으로,
없는 페이지를 임의로 만들지 않는다.

### 3. 기존 문구 정리

현재 있는 "보험금 청구 관련 바로가기는 청구창구에서 확인하세요" 한 줄 문구는 새 nav로 대체되므로
제거한다(중복 방지). 서비스 설명 문구, 카피라이트 줄은 유지한다.

### 4. 스타일

기존 디자인 시스템 토큰 재사용 — 컬럼 제목은 `text-[12.5px] font-bold text-muted` 계열의 작은
레이블, 링크는 `text-[13px] font-semibold text-muted hover:text-accent` + `transition-colors`
(150-300ms, MASTER.md 기준). 모바일(`sm` 미만)에서는 2단 그리드가 1단으로 스택. 새 외부 링크에도
기존 청구친구 링크와 동일하게 같은 탭에서 열리는 방식(target 미지정)을 유지한다.

## Non-goals

- 청구친구 저장소(`claim-zucca100`)의 파일은 수정하지 않는다(별도 리포지토리).
- 모바일 앱형 고정(sticky) 하단 탭바는 만들지 않는다 — 일반 푸터 내 섹션이다
  (MASTER.md 안티패턴: "No content hidden behind fixed navbars").
- 청구친구 외 다른 zucca100 포트폴리오 사이트는 현재 존재하지 않으므로 추가 교차 링크는 만들지
  않는다.

## Testing

- `npm run build` 성공 확인(정적 생성 페이지 수 기존과 동일해야 함 — 새 컴포넌트만 추가, 라우트
  변경 없음).
- 브라우저에서 모바일/데스크톱 너비로 푸터 nav 줄바꿈 확인.
- 각 링크의 `href`가 설계안 표와 일치하는지 확인.
